# 智能巡检机器人推荐控制方案

采用树莓派5运行Python巡检与视觉程序，STM32F407运行C语言实时控制。树莓派通过USB转3.3V TTL串口连接STM32 USART2（PA2 TX、PA3 RX），115200、8N1，交叉接线并共地。不使用树莓派GPIO直连动力设备。

## 硬件配置建议

- 双24V直流减速电机，配增量编码器；驱动器采用支持PWM/DIR和硬件使能的工业直流驱动器。具体额定电流、减速比须依据85kg平台牵引力和电机堵转电流选择，不能按教学小车驱动器选型。
- STM32通过TIM3/TIM4采集左右编码器，TIM1输出两路驱动PWM。建议TIM3 PA6/PA7、TIM4 PB6/PB7；PWM TIM1 PA8/PA9；DIR PC0/PC1；驱动使能PC2。实际板卡需在CubeMX检查复用冲突。TIM3/4为16位计数器，差分按有符号16位回绕处理。
- 五关节及夹爪优先使用带位置、电流反馈的总线伺服，经过独立RS485收发器连接USART3 PB10/PB11，PB12控制收发方向。协议与型号尚未确定，因此不编造舵机指令。16kg机械臂必须按关节力矩选型，不能直接套用小型PWM舵机。
- 编码器及传感器接入前核实电平，5V/24V信号必须经过电平转换或隔离。BMS提供SOC，所有运动方向的测距传感器提供有效净空。单个前超声波不足以支持安全倒车或原地回转。
- 急停直接切断驱动使能，独立于软件；充电器与BMS匹配。

## 文件用途与接入步骤

1. 用STM32CubeMX建立F407 HAL工程，将control.c和control.h加入。主循环中以HAL_GetTick()调用control_step()；control_init()在外设初始化后执行。启用硬件看门狗，完成循环后喂狗。
2. 编写board.c，实现头文件内5个硬件函数。board_sensors必须返回最近采集反馈；过期、测距失败、任一方向盲区、BMS丢失、伺服故障均置valid=false或driver_fault=true。PWM符号映射电机方向，过零反转需由驱动器/适配层实施死区与限流。
3. board_arm_start实现非阻塞标定轨迹，轨迹0收拢、1观察；每次启动都清除到位标志，达到真实位置后才更新反馈。关节限位与闭链联动由伺服适配层完成。缺少标定时返回false，禁止假装动作成功。
4. USART接收使用DMA环形缓冲区，按A5 5A查找16字节帧，CRC通过后在主循环调用control_frame。不要在中断中直接执行控制函数。限制缓冲区长度并对错帧重新同步；不回放旧帧。序号目前用于调试，不提供防重放保护。
5. 树莓派安装pyserial，修改pi_link.py中的端口。默认入口仅停车；确认抬起履带、急停有效并完成标定后，才能显式enable并以20Hz发送drive。机械臂动作期间发送heartbeat，但不要发送底盘运动指令。

协议：A5 5A、版本01、命令1字节、序号uint16、参数a float32、参数b float32、CRC16/Modbus，共16字节，小端。命令0停车并去使能；1使能；2线速度/角速度；3机械臂预设；4心跳。任意错误反馈触发锁存故障，需检修后重启控制器。通信超时250ms去使能；观察动作必须停车。

## 参数与实现边界

履带中心距0.50m、速度上限0.20m/s、净空0.50m、PI增益、电池阈值均为初始配置，未经实机验证。必须替换为实测值，并验证全载制动和姿态稳定性。低电量回充由原robot_core.py状态机调度，不能靠SOC直接盲走。

现有包提供核心控制与发送协议，不是完整可烧录固件：尚缺board.c、CubeMX初始化、总线伺服协议、双向状态遥测、地图定位、仪表识别模型及充电对接控制。pi_link.py可被上一版robot_core.py的IO适配器调用；反馈接口未接通前禁止让巡检状态机驱动设备。按钮按压需另行标定并授权，默认不执行。
